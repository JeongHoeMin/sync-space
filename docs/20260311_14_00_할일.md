**SyncSpace 프로젝트 제안서 및 기획서
1. 프로젝트 개요**
• 
**프로젝트명**: SyncSpace - 인터랙티브 화상 협업 플랫폼 

• 
**목표**: 원격 근무 및 스터디 환경에서 단순한 화면 공유를 넘어, 공유된 화면 위에 실시간으로 그림을 그리며 소통할 수 있는 데스크톱 전용 몰입형 커뮤니케이션 툴 개발.

• **타겟 유저**:
    ◦ 원격으로 코드를 리뷰하거나 디자인을 함께 수정해야 하는 개발자 및 디자이너.

    ◦ 화면을 보며 즉각적인 피드백과 표시가 필요한 온라인 튜터 및 학생.

**2. 핵심 가치 (Core Value)**
• 
**Interactive**: WebRTC 데이터 채널을 활용한 지연 없는 초저지연 양방향 화면 판서 기능.

• 
**Seamless**: 브라우저 탭의 한계를 벗어난 Electron 기반의 독립적이고 쾌적한 데스크톱 경험 제공.

• 
**Cost-Effective**: 오픈소스 SFU(LiveKit)와 클라우드 무료 티어를 조합한 유지보수 비용 최소화.

**3. 핵심 아키텍처 및 기술 스택**
프로젝트의 풀스택 언어는 TypeScript를 사용하여 타입 안정성을 극대화합니다.

• 
**Frontend (Desktop)**: Electron, React, Tailwind CSS.

• 
**Backend (API/Signaling)**: NestJS, Socket.io, Zod (API 페이로드 및 소켓 데이터 스키마 철저한 검증용).

• 
**Media Server (SFU)**: LiveKit Server.

• 
**Database & Storage**: PostgreSQL, AWS S3.

**개발 마일스톤 및 세부 계획 (단계별)**
기간 구분이 아닌 **기능 완성 단계(Phase)**를 기준으로 마일스톤을 재편했습니다. 프론트엔드와 백엔드 담당자는 각 단계가 완전히 맞물려 완료된 후 다음 단계로 넘어가야 합니다.
**1단계: 코어 인프라 구축 및 사용자 인증 시스템**
현재 하드코딩된 사용자 및 더미 연결을 실제 데이터베이스 연동 및 인증으로 교체하는 단계입니다.
• **백엔드 (sync-space-server)**:
    ◦ REST API (NestJS)를 통한 이메일/비밀번호 기반 회원가입 및 로그인 API 구현.

    ◦ JWT 발급 로직 연동 및 Zod 라이브러리를 활용한 서버 진입점 데이터 스키마 검증.

    ◦ PostgreSQL DB 세팅 및 `users`, `channels`, `channel_participants`, `messages` 테이블 생성 로직 안정화.
• **프론트엔드 (sync-space-app)**:
    ◦ Electron 앱 내 로그인/회원가입 UI 스크린 구현.
    ◦ API 연동 후 발급받은 JWT를 로컬 세션에 안전하게 저장 및 상태 관리 로직(Zustand 등) 구축.
**2단계: 채널(방) 관리 및 LiveKit 연동 고도화**
현재 `App.tsx`의 임시 테스트 접속 로직을 제거하고, 동적인 채널 생성/입장 시스템을 구축합니다.
• **백엔드 (sync-space-server)**:
    ◦ 새로운 음성/화상 채널 생성 및 기존 채널 입장 API 구현.

    ◦ 클라이언트가 특정 채널에 입장할 때, 해당 채널에 접근할 수 있는 LiveKit Token을 생성하여 반환하는 API 구현.

    ◦ 고유 접속 링크를 통한 채널 참여 로직 및 `app.gateway.ts`의 접속자 목록 실시간 갱신 고도화.

• **프론트엔드 (sync-space-app)**:
    ◦ 메인 대시보드 (채널 목록, 채널 생성, 초대 링크 입력 UI) 구현.
    ◦ `App.tsx`에서 하드코딩된 `fetch('http://localhost:3000/livekit/token')` 부분을 실제 인증 토큰을 담은 API 호출로 교체.
    ◦ 채널 입장 시 사이드바에 현재 접속자 목록 및 `app.gateway.ts`와 연동된 실시간 텍스트 채팅창 UI 추가.

**3단계: 화면 공유 및 초저지연 양방향 판서 기능 고도화 (핵심 구현)**
현재 캔버스에 구현된 단순한 드로잉 기능을 다대다 환경에서 완벽하게 동작하도록 완성합니다.
• **프론트엔드 (sync-space-app)**:
    ◦ 사용자가 자신의 데스크톱 전체 화면 또는 특정 애플리케이션 창을 선택하여 공유하는 UI/UX 완성.

    ◦ 화면 공유자(발신자): 화면 위에 투명한 Canvas 오버레이를 띄우고, 클릭 통과(Click-through) 속성을 제어하여 판서 모드 활성화 시에만 드로잉 이벤트를 캡처하도록 구현.

    ◦ 시청자(수신자): 비디오 스트림 위에 HTML5 캔버스를 겹쳐 띄우고, 마우스 좌표 데이터를 추출.

    ◦ 펜 굵기, 색상 변경, 지우개, 전체 지우기 등 드로잉 툴바 UI 추가.
    ◦ WebRTC DataChannel을 통해 0.5초 이내에 시청자와 공유자의 화면 양방향으로 좌표가 동기화되도록 데이터 패킷 최적화.

• **백엔드 (sync-space-server)**:
    ◦ 1개 채널 당 최소 10명의 동시 화상 통화 및 화면 공유가 원활히 작동하도록 LiveKit SFU 서버의 리소스 및 설정 최적화.

    ◦ 도메인 주도 설계(DDD) 관점을 차용한 헥사고널 아키텍처를 완벽히 적용하여 비즈니스 로직 분리.

**4단계: 파일 시스템 연동 및 최종 패키징**
사용자 편의 기능 추가 및 상용 배포를 위한 패키징을 진행합니다.
• **백엔드 (sync-space-server)**:
    ◦ AWS S3 연동을 통한 이미지/파일 직접 업로드 처리 및 URL 생성.

    ◦ 생성된 파일 URL을 Socket.io를 통해 채팅창에 브로드캐스팅하는 로직 추가.

    ◦ API 서버, DB, Media 서버를 Docker 컨테이너 단위로 패키징하여 배포 준비.

• **프론트엔드 (sync-space-app)**:
    ◦ 채팅창에 이미지 파일 드래그 앤 드롭 전송 기능 구현.

    ◦ Electron 빌드 설정을 통한 Windows/Mac용 설치 파일(Installer) 패키징.
**개발팀 당부사항**
• **프론트엔드 개발자**: 현재 `App.tsx`에 작성해주신 Canvas 오버레이와 LiveKit 뼈대는 훌륭합니다. 다음 작업으로는 임시로 작성된 `fetch` 로직을 실제 유저 인증 플로우로 교체하고, Electron의 `desktopCapturer`로 불러온 화면들을 예쁘게 렌더링할 수 있는 UI 컴포넌트 분리에 집중해 주시기 바랍니다.
• **백엔드 개발자**: `app.gateway.ts`에 TypeORM 엔티티가 잘 연결되어 있습니다. 소켓을 통한 채팅 기반은 마련되었으니, 우선적으로 NestJS REST API 기반의 JWT 인증 컨트롤러와 LiveKit 서버에서 안전하게 토큰을 발급받을 수 있는 서비스 계층(`LivekitService`) 구현을 1순위로 진행해 주시기 바랍니다.
