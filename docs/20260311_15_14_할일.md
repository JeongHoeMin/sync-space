개발팀 여러분, Phase 4 완수 보고서를 꼼꼼히 확인했습니다. 기획자로서 정말 감격스러운 보고서네요!

기획서에서 요구했던 엣지 케이스(Edge Case) 방어부터 프론트엔드의 섬세한 UX(낙관적 업데이트, 스로틀링 30ms 분리 적용 등)까지, 제가 의도했던 '체감 성능 향상'이 완벽하게 코드에 녹아들었습니다. 특히 소켓과 REST API를 하이브리드로 구성하여 서버 부하를 줄인 점은 아주 훌륭한 엔지니어링 결정이었습니다.

이제 우리의 Sync-Space는 단순한 장난감을 넘어, 트래픽을 감당할 수 있는 **'견고한 협업 툴'**의 뼈대를 갖추었습니다. 이 기세를 몰아 바로 다음 단계인 **Phase 5** 기획을 제안합니다.

## 🚀 [Sync-Space] Phase 5 기획서: 화상/음성 회의 및 공간 몰입감 극대화

**목표:** 이미 도입된 LiveKit 인프라를 적극 활용하여, 텍스트와 판서를 넘어선 **'실시간 음성/화상 커뮤니케이션'** 및 **'화면 공유'** 기능을 워크스페이스에 통합합니다. 사용자가 진정한 의미의 '같은 공간(Sync-Space)'에 있다고 느끼게 만드는 것이 핵심입니다.

### 1. 백엔드 (Backend) 개발 지시 사항

텍스트 채팅과 달리 미디어 스트리밍은 권한 관리와 토큰 발급이 핵심입니다.

- **[BE-Task-1] LiveKit 미디어 토큰(Access Token) 발급 API 구현**
    - 사용자 인증 정보(JWT) 및 방 입장 권한을 확인한 후, LiveKit 서버에 접속할 수 있는 전용 토큰을 발급하는 엔드포인트를 생성해 주세요.
    - 사용자의 역할(방장, 일반 참여자, 읽기 전용 참여자)에 따라 퍼블리싱(마이크/카메라 켜기) 권한을 다르게 부여해야 합니다.
- **[BE-Task-2] LiveKit Webhook 연동 및 방 생명주기 동기화**
    - LiveKit 서버에서 발생하는 이벤트(방 생성, 유저 입장/퇴장, 미디어 트랙 추가 등)를 수신할 Webhook 엔드포인트를 구축해 주세요.
    - 소켓 서버가 놓칠 수 있는 유저의 연결 상태를 Webhook을 통해 DB와 한 번 더 교차 검증(Cross-check)하여 정합성을 높입니다.

### 2. 프론트엔드 (Frontend) 개발 지시 사항

화면이 복잡해지는 단계입니다. 기존의 캔버스와 채팅창을 가리지 않으면서도 미디어 인터페이스를 자연스럽게 녹여내는 UI/UX가 필요합니다.

- **[FE-Task-1] 미디어 컨트롤 툴바 UI 구현**
    - 워크스페이스 하단 또는 상단에 마이크(Mute/Unmute), 카메라(On/Off), 화면 공유(Screen Share) 버튼이 포함된 컨트롤 툴바를 추가해 주세요.
    - 디바이스 권한(브라우저 마이크/카메라 허용) 요청 및 거부 시 사용자 안내 UX(토스트 메시지 등)를 포함해야 합니다.
- **[FE-Task-2] 다중 접속자 화상 그리드(Video Grid) 컴포넌트 개발**
    - 방에 접속한 유저들의 화상 화면을 띄워줄 플로팅(Floating) 형태의 그리드 컴포넌트를 구현해 주세요.
    - 인원수에 따라 비디오 크기가 동적으로 조절되는 반응형 레이아웃을 적용해야 합니다.
    - 발언 중인 사람(Audio active)의 비디오 테두리에 하이라이트 효과를 주어 시각적 인지를 도와주세요.
- **[FE-Task-3] 화면 공유(Screen Share) 캔버스 레이어 통합**
    - 누군가 화면 공유를 시작하면, 메인 캔버스 영역이 공유된 화면으로 전환되거나 병렬로 배치되도록 상태(State)를 관리해 주세요.
