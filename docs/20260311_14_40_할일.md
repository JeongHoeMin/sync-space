기획자로서 개발팀이 즉시 스프린트 보드(Jira, GitHub Projects 등)에 티켓으로 등록하고 작업에 착수할 수 있도록, Phase 4의 지시 사항을 **최소 단위의 태스크(Task)와 수용 조건(Acceptance Criteria, AC)**으로 잘게 쪼개어 드리겠습니다.

기간(일정)은 배제하고, **논리적인 작업의 선후 관계(단계)**에 따라 구성했습니다.

## 📋 [Sync-Space] Phase 4 상세 작업 분할 구조도 (WBS)

### 🛠️ 백엔드 (Backend) 파트 태스크

### **[BE-Task-1] 채팅 내역 커서 기반 페이지네이션 API 구현**

- **작업 단계:** 데이터 조회 로직 개편
- **상세 내용:** 기존의 `최근 50개 조회` API를 커서(Cursor) 기반 무한 스크롤이 가능하도록 수정.
- **수용 조건 (AC):**
    - 클라이언트가 쿼리 파라미터로 `cursor` (마지막 메시지 ID 또는 생성 시간)를 보낼 수 있어야 함.
    - 응답 데이터에 `messages` 배열 외에 `nextCursor`, `hasNextPage` (다음 페이지 존재 여부 boolean)가 포함되어야 함.
    - `cursor` 값이 없을 경우 가장 최근 메시지 N개를 반환해야 함.

### **[BE-Task-2] Multer 기반 파일 업로드 보안 및 예외 처리**

- **작업 단계:** 미들웨어 설정 및 에러 핸들링
- **상세 내용:** 무분별한 업로드를 막기 위한 파일 검증 로직 추가.
- **수용 조건 (AC):**
    - 용량 제한: 단일 파일 업로드 시 20MB를 초과하면 HTTP 413 상태 코드를 반환해야 함.
    - 확장자 제한: `mimetype`을 검사하여 허용된 포맷(이미지, pdf, zip 등)이 아니면 HTTP 415 상태 코드를 반환해야 함.
    - 파일명 난독화: 업로드 시 원본 파일명 대신 `UUID + 확장자` 형태로 서버에 저장되어야 함 (한글/특수문자 에러 방지).

### **[BE-Task-3] 소켓(Socket.io) 연결 안정성 강화**

- **작업 단계:** 실시간 통신 예외 처리
- **상세 내용:** 비정상 종료 시 발생하는 '유령 유저' 문제 해결 및 상태 동기화.
- **수용 조건 (AC):**
    - 클라이언트 비정상 종료 시(브라우저 강제 종료, 네트워크 끊김 등) 최대 N초 이내에 서버가 이를 감지하고 해당 유저를 방에서 `leave` 처리해야 함.
    - 서버에서 유저의 연결 해제가 확정되면, 방에 남은 다른 유저들에게 `user-disconnected` 이벤트를 즉시 브로드캐스팅해야 함.

### 🎨 프론트엔드 (Frontend) 파트 태스크

### **[FE-Task-1] 채팅창 무한 스크롤 UI 적용**

- **작업 단계:** [BE-Task-1] 완료 또는 모킹(Mocking) 후 진행
- **상세 내용:** 사용자가 채팅창을 위로 스크롤할 때 이전 대화를 자연스럽게 불러오기.
- **수용 조건 (AC):**
    - `Intersection Observer`를 사용하여 채팅 컨테이너 최상단 도달 시 이전 데이터 API를 호출해야 함.
    - 이전 데이터를 불러와 화면에 렌더링한 후에도, 스크롤 위치가 맨 위로 튕기지 않고 **사용자가 보던 메시지 위치를 유지**해야 함.

### **[FE-Task-2] 낙관적 업데이트(Optimistic UI) 기반 채팅 전송**

- **작업 단계:** UI 반응성 개선
- **상세 내용:** 서버 응답 대기 시간을 없애 체감 전송 속도 향상.
- **수용 조건 (AC):**
    - 사용자가 전송 버튼을 누르면, 서버 응답이 오기 전에 먼저 로컬 채팅 목록(UI)에 메시지를 추가해야 함.
    - 이때 메시지 옆에 '전송 중(⏳)' 표시를 띄우고, 서버에서 성공 응답이 오면 제거해야 함.
    - 서버 전송 실패 시 해당 메시지를 빨간색 등으로 표시하고 '재전송' 버튼을 노출해야 함.

### **[FE-Task-3] 파일 업로드 Drag & Drop 및 Progress Bar 구현**

- **작업 단계:** [BE-Task-2] 연동
- **상세 내용:** 직관적인 파일 업로드 경험 제공.
- **수용 조건 (AC):**
    - `ChatPanel` 영역에 파일을 드래그해서 올리면 '이곳에 파일을 놓으세요' 형태의 오버레이(Dropzone) UI가 노출되어야 함.
    - 드롭 즉시 업로드가 시작되며, 업로드 진행률(0~100%)을 보여주는 Progress Bar 컴포넌트가 채팅창에 표시되어야 함.
    - 20MB 초과 등 업로드 실패 시 사용자에게 명확한 토스트 알림(Toast Error)을 띄워야 함.

### **[FE-Task-4] 캔버스 판서/지우개 렌더링 최적화**

- **작업 단계:** 렌더링 부하 및 네트워크 패킷 최적화
- **상세 내용:** 다중 사용자 환경에서 드로잉 랙(Lag) 최소화.
- **수용 조건 (AC):**
    - 마우스 이동(`mousemove`) 이벤트 발생 시 `requestAnimationFrame`을 적용하여 브라우저 렌더링 주기에 맞춰 드로잉을 업데이트해야 함.
    - LiveKit/Socket으로 좌표 데이터를 전송할 때 `Throttling`(예: 16ms~30ms 간격)을 적용하여 불필요한 네트워크 요청 횟수를 줄여야 함.
